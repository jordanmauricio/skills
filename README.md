# skills

My curated agent skills: my own, plus pinned copies from upstream sets.

Agent-agnostic by design — plain `SKILL.md` files, consumed by **Claude Code** and
**Codex** from one canonical tree. Claude Code's plugin manifest is an adapter over that
tree, not the source of truth.

Plan of record: [`dotfiles/docs/skills.md`](https://github.com/jordanmauricio/dotfiles/blob/main/docs/skills.md).

## Install

```bash
# global, Claude Code + Codex only
npx skills@latest add jordanmauricio/skills -s '*' -a claude-code -a codex -g -y

# Claude-native: namespacing, subagents, eval, token accounting
claude plugin marketplace add jordanmauricio/skills --scope user
claude plugin install jordan-core@jordan
```

`-a` must be repeated; comma-separated values are rejected. **Do not use `--all`** — it is
shorthand for `--skill '*' --agent '*'` and silently overrides `-a`, installing into ~50
agent directories in `$HOME`.

Skills land as real copies in `~/.agents/skills/`, with `~/.claude/skills/*` symlinked to
them. That copy — not this repo — is what the agents read, so re-run the command (or
`npx skills update -g`) after changing anything here.

## Layout

```
packs/core/
├── .claude-plugin/plugin.json   generated by sync-vendor.sh — do not hand-edit `skills`
├── skills/mine/<name>/          mine
├── skills/vendor/<name>/        pinned upstream, machine-written
└── agents/                      Claude subagents (do not port to other agents)
```

## Mine

| Skill | For |
|---|---|
| `flow` | Route a task to the right skill in this set |
| `web-perf-audit` | A page loads slowly, or a Core Web Vital needs explaining, from a browser trace |
| `spike-triage` | A production latency or error spike on Google Cloud: find the hop that added the time, and why |

Vendored skills are listed in [`vendor.yaml`](./vendor.yaml).

## Updating vendored skills

Edit [`vendor.yaml`](./vendor.yaml), bump a `ref`, then:

```bash
./scripts/sync-vendor.sh
```

Read the resulting `git diff` — that is exactly what upstream changed.

> **The fork rule.** Never hand-edit anything under `skills/vendor/`. It is wiped and
> rewritten on every sync. To change a vendored skill, move it to `skills/mine/`, rename
> it, and delete its line from `vendor.yaml`.

## Constraints that bite

- **Depth**: `SKILL.md` must sit at most **5 directory levels** below the repo root.
  Deeper is *silently skipped* by `npx skills` while still working as a Claude plugin —
  a Codex-only, no-warning failure. `sync-vendor.sh` hard-fails on it.
- **Names are flat and global** in the universal skills dir; Claude's `pack:skill`
  namespacing does not exist there. No two skills may share a name. `sync-vendor.sh`
  hard-fails on collisions.
- **Portability**: only `name` and `description` frontmatter is universal.
  `disable-model-invocation` is Claude-only, so user-invoked-only skills become
  model-invokable elsewhere. Subagents under `agents/` do not port at all.
